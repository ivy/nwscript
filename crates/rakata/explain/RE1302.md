A `gff set` assignment that does not parse as its field's type.

`rakata gff set` takes each assignment as `PATH=VALUE` or `PATH=TYPE:VALUE`. Without a type, the value is read as the type of the field already at `PATH`; with one, as that type. The value given is not one the type holds, or the assignment has no `=`, or it names a `Struct` or `List`, which are set field by field.

```text
error[RE1302]: `300` is not a BYTE value
error[RE1302]: a Vector is 3 comma-separated floats, not `1,2`
error[RE1302]: `Tag` is not PATH=VALUE or PATH=TYPE:VALUE
```

The forms each type takes: integers in decimal within the type's range (`byte`, `char`, `word`, `short`, `dword`, `int`, `dword64`, `int64`); `float` and `double` as decimals; `string` as text, which must be in the game's code page (Windows-1252); `resref` as at most sixteen bytes; `strref` as a number, `-1` for none; `vector` and `orientation` as three or four comma-separated floats; `void` as hexadecimal digits; `locstring` as a strref number (`-1` for none), which keeps the embedded substrings, or `ID=TEXT`, which sets the substring with string id `ID` (the language id times two, plus one for the feminine form).
