A list entry names a section the change file does not have.

A `ChangeRow12=repeating_blaster` under `[baseitems.2da]` means "apply the keys of `[repeating_blaster]`"; a `File0=x.utc` under `[GFFList]` means "apply `[x.utc]`". When the file has no such section, TSLPatcher logs the entry and skips it, and so does `rakata`: the plan goes on without that operation. The usual cause is a row or file copied from another changes file whose sections did not come along.

```text
warning[RW0301]: `ChangeRow12=repeating_blaster` in [baseitems.2da] names a section `[repeating_blaster]` the file does not have; skipped
```

Add the missing section, or remove the entry if the operation was not meant for this file. For an `install_folder#` entry the section is named by the key, not by the folder it points to.
