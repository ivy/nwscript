Bytes after the last keyframe of a lip-sync file.

A lip-sync file ends with its last keyframe: nothing follows, and the file's length is exactly 16 + 5 × count. Every file the game ships and every file the community's tools write has this length. The file read is longer, so bytes follow the last keyframe that the layout gives no meaning to.

```text
error[RE0904]: 3 bytes follow the last keyframe
```

The reader refuses rather than drop the bytes silently, since a round trip would then write a different file. Whether the engine ignores a trailer is not established. Check how the file was produced; a count at offset 12 lower than the keyframes actually written gives the same symptom.
