A round trip wrote bytes the format's own reader rejects.

`rakata conformance` reads a file with a format's reader, writes it with the format's writer, and when the bytes differ reads the written bytes again to decide whether the two readings agree. Here the second reading failed: the writer produced a file the reader will not accept. The message carries the reader's own diagnostic for the written bytes.

```text
error[RE0502]: modules/danm13.rim: the written bytes do not re-read: RE0202: the resource table at offset 120 for 7040 bytes lies beyond the end of the 4096-byte file
```

This is a defect in the writer, never in the file: report it with the file's name and the diagnostic. The file itself is classified as different, so the run exits 3.
