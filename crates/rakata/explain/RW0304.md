A memory token read before anything sets it.

`2DAMEMORY#` tokens carry a value from one operation to a later one (a row index an `AddRow` stored, read by a GFF field) and `StrRef#` tokens carry the dialog.tlk index an appended entry received. The phases run in a fixed order (TLKList, InstallList, 2DAList, GFFList, HACKList, CompileList, SSFList) and within a phase in the order listed, so a token is only set when an earlier operation in that order stores to it. TSLPatcher's documentation says of a token read before it is set that "bad things will happen"; `rakata` reports the read.

```text
warning[RW0304]: `2DAMEMORY3` is read here, and nothing before this operation sets it
```

Move the operation that sets the token ahead of the one reading it, or add the missing `2DAMEMORY#=RowIndex` (or `StrRef#=` under `[TLKList]`).
