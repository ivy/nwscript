An instruction's second byte, its type, is not one its opcode takes.

Each opcode takes a fixed set of type bytes: `ADD` takes `II`, `IF`, `FI`, `FF`, `SS` and `VV`; `CPDOWNSP` takes only `0x01`; `JMP` only `0x00`. The type byte decides the operand layout, so an unknown pairing leaves the decoder with no way to tell how long the instruction is, and it stops rather than guess.

```text
error[E0104]: GT does not take type 0x23 (at offset 412)
```

Here `GT` was given `SS`, a string comparison the engine does not provide. Recompile the script; if another tool produced the bytes, the pairing is a bug in that tool.
