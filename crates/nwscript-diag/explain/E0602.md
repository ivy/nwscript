A function in the decompiler's output is not known to be what the bytecode says. The decompiler recompiles the source it recovers and compares each function's instructions with the original's; this function either recompiled to different instructions (`unverified`, with the original offset of the first difference) or has a shape the decompiler cannot read back (`not recovered`, with the reason). The output marks the function with a comment saying which.

```text
$ nws --nwscript nwscript.nss decompile k_my_script.ncs -o k_my_script.nss
warning[E0602]: sub_1a4: unverified: recompiles differently from offset 512
```

An unverified function's source is the decompiler's best reading: compare `nws disasm` of the original with the recompiled bytecode from that offset to see what differs. A function that was not recovered appears as a placeholder with its signature, so the rest of the script still compiles. Some differences are the verifying compiler's rather than the decompiler's: nwnnsscomp, the interim verifier, does not reproduce BioWare's bytes for every construct. `--strict` makes any such function exit with status 3.
